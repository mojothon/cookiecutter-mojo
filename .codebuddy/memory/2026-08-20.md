- `{{cookiecutter.project_slug}}/pixi.toml`:`mojo = ">=1.0.0"`(用户已改),我清理了 channels 列表尾随空格、补了文件末尾换行。

### 验证(Mojo 1.0.0 实测)
- `pixi install` + `pixi run mojo --version` → 1.0.0(来自 conda.modular.com/max/,构建日期 2026-08-09)。
- `pixi run test` → 通过,输出 "test"。
- 包导入 `from <pkg>.version import __version__`、`from <pkg>.index import index` 正常(相对导入语法在 1.0.0 下有效)。
- `mojo precompile <pkg>` 必须从包含包目录的目录运行(rattler-build 的 src 工作目录下 OK);`mojo precompile <dir> -o out.mojoc` 也可用;`.mojoc` 可被 `mojo run -I` 正确加载。
- `rattler-build build -r src` 完整构建成功,`all tests passed!`,生成 .conda 包,run deps `mojo >= 1.0.0`。有一个非阻塞警告 "Overdepending against mojo"。

- 模板默认 `project_slug` 由 `project_name.lower().replace(' ', '-')` 生成,若 project_name 含空格则 slug 带连字符,Mojo 包目录名非法(模块名不能含 `-`)。用户生成项目时应避免空格,或模板需改进 slug 生成逻辑。未改动(超出本次迁移范围)。
- 现有 Mojo 源码均为现代语法(comptime 版本常量、def main),无需语法迁移。
